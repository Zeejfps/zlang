# TXI: texture info

A TXI is a short text of `keyword value` lines that tells the engine how to use a texture: blending,
sampling, environment and bump maps, flipbook animation, procedural generation, and, for font
textures, where each glyph is. It has no binary header and no version.

Resource type **2022** (`txi`), ASCII text. Type ids are in [resource-types.md](resource-types.md);
the texture lookup (TPC versus TGA, and which source wins) is in
[resources.md](resources.md#textures-tpc-tga-txi). This document gives the syntax and the best-known
meaning; the rendering agent refines what each keyword does on screen in
[txi-render.md](txi-render.md), and the TPC pixel layout is in [tpc.md](tpc.md).

## Where the game keeps it

TXI text lives in two places, and in the shipped data never both for one name:

1. **Standalone `.txi` resources**: 5,616 copies, all distinct resrefs.
   - 5,586 in `data/lightmaps*.bif`, next to the area lightmap TGAs: 5,474 say
     `islightmap 1 / compresstexture 0 / mipmap 0 / downsamplemax 0`, 112 say
     `mipmap 0 / downsamplemax 0`.
   - 28 in `data/textures.bif`, 1 in `data/templates.bif` (`grass`), 1 in `swpc_tex_gui.erf`
     (`lbl_menudarr`).
   - 5,600 pair with a TGA of the same name; `grass` pairs with a TPC that carries no TXI of its
     own; 15 pair with no image at all: the procedural textures `distortiontex` and `filmnoisetex`
     (generated by the engine; both names are strings in the exe), `grassinfo` (not a TXI, see
     [Quirks](#quirks)), and 12 orphans whose texture is gone.
2. **Appended to TPC textures**: 6,207 of the 11,536 TPC copies (3,055 distinct resrefs) carry TXI
   text after their pixel data: 1,576 in each of the three quality packs `swpc_tex_tpa/tpb/tpc.erf`,
   1,470 of the 1,570 in `swpc_tex_gui.erf`, 9 of the 84 in `patch.erf`. The three quality packs
   carry the same TXI text for the same name.

**Lookup.** For texture *X*: if a `X.txi` resource is found, use it; otherwise use the text appended
to `X.tpc`, if the texture came from a TPC. This order is our decision, not a finding: the shipped
data never has both for one name, so it cannot tell, and what swkotor.exe does is an open question
for reverse engineering. We pick the standalone file because it is the separately addressable
resource: a `.txi` placed in Override can then change a texture's options without rebuilding its
TPC. A texture with no TXI uses the defaults below.

## TXI inside TPC

To find the text, compute where the pixel data ends. The 128-byte TPC header (full description in
[tpc.md](tpc.md)):

| Offset | Size | Type | Meaning |
|---|---|---|---|
| 0 | 4 | u32 | data size: 0 for uncompressed; otherwise see below |
| 4 | 4 | float32 | (not needed here) |
| 8 | 2 | u16 | width *w* |
| 10 | 2 | u16 | height *h* |
| 12 | 1 | u8 | encoding: 1 grey, 2 RGB / DXT1, 4 RGBA / DXT5 |
| 13 | 1 | u8 | mip level count *m* |
| 14 | 114 | | zero |

Rule (it holds for all 11,536 copies):

1. Compressed if data size != 0: encoding 2 is DXT1 (8 bytes per 4x4 block), 4 is DXT5 (16).
   A level of size *w* x *h* takes `max(1, ceil(w/4)) * max(1, ceil(h/4)) * block` bytes.
   Uncompressed: `w * h * 1, 3 or 4` bytes for grey, RGB, RGBA.
2. Each level halves width and height (never below 1).
3. **Cube map** if *h* = 6*w*: six square faces of *w* x *w*, each with its own *m* levels, one face
   after another (189 copies; their TXI always says `cube 1`).
4. Standard size = faces x (sum of the *m* level sizes).
5. **Flipbook** if compressed and data size > standard size: the pixel data is exactly *data size*
   bytes (121 copies). These all have *m* = 1 in the header, and their TXI says
   `proceduretype cycle` with `numx`/`numy`: the data is `numx * numy` frames of
   `(w/numx) x (h/numy)`, each with a full mip chain down to 1 x 1 (checked for all 121).
6. Otherwise the pixel data is the standard size. (The data size field is the top level's size for
   ordinary compressed textures, so it is not the total; 23 copies of 2 x 2 and 4 x 4 DXT1
   textures even say 16, a DXT5 block.)
7. Everything after `128 + pixel bytes` is TXI text, possibly empty. In the shipped data it is
   always printable ASCII plus CR, LF and tab, with no NUL padding.

## Grammar

```
txi     = { line } ;
line    = [ ws ] [ keyword { ws value } ] [ ws ] newline ;
block   = keyword ws count newline count * ( number { ws number } newline ) ;
ws      = 1*( " " | TAB ) ;
newline = CR LF | end of text ;
```

What the data shows, and the reader rules we take from it:

- **Lines** end in CRLF everywhere (no bare LF or CR in any file). 883 texts have no final newline,
  324 TPC texts are a single line without one. Blank lines are common (972 texts). Treat CR, LF and
  CRLF as line ends and skip blank lines.
- **Whitespace**: tokens are separated by one or more spaces or tabs (`isdiffusebumpmap  1`,
  `defaultwidth  32`); 1,690 texts have trailing spaces or a trailing tab (`arturowidth 64<TAB>`);
  82 begin with a blank line or a space. Split each line on any run of spaces and tabs.
- **Keywords** are the first token. Mostly lower case, but `Bumpyshinytexture`, `Bumpmaptexture`,
  `Decal`, `Type` and the font keywords `spacingR`/`spacingB` occur (the exe's own table spells
  `spacingR` and `spacingB` that way). Match keywords **case-insensitively**.
- **Values** are the remaining tokens: integers (`0`, `256`), decimals (`0.125`, `-0.010000`) and
  decimals with no leading digit (`.5`, 50 of them). No exponents, no `+`. Texture names are
  resrefs in any case (`CM_Baremetal`, `cm_baremetal`): fold them to lower case.
- **Blocks**: four keywords take a count and are followed by that many lines of numbers only:
  `upperleftcoords N` and `lowerrightcoords N` (lines of three numbers), `channelscale N` and
  `channeltranslate N` (lines of one number). A line whose first token is a number belongs to the
  block before it. One texture breaks the count: `lma_caus01` has `channelscale 1` and
  `channeltranslate 1` each followed by four lines of `1`. Decision: keep reading numeric lines
  into the block regardless of the count (up to 4 for the channel blocks); for this texture every
  reading gives scale 1 and offset 1 anyway.
- **Comments**: none in the data (no `#`, `//` or `;` anywhere). Don't invent a comment syntax.
- **Repeats**: a keyword may appear twice (`mipmap 0` twice in `lsf_lit01`; `bumpyshinytexture`
  twice). The later one wins; in the data the values are always equal.
- **Unknown keywords and bad values are ignored**, not errors: the shipped files contain keywords
  the engine never reads (below) and misspellings (`blending addititive`, `compresstexure`,
  `compress texture`, `bumpmapscale`).

## Keywords

Counts are distinct resrefs whose TXI uses the keyword (standalone .txi / appended to TPC). "Exe"
says whether the keyword string is in swkotor.exe: the exe holds one table of TXI keywords
(between `NormCubeMap` and `.txi`), a second one of procedural parameters, and the material
keywords next to the model code. A keyword whose string the exe lacks cannot be matched by a
string compare, so the game almost certainly never reads it.

### Blending and sampling

| Keyword | Args | Resrefs | Exe | Meaning (best known) |
|---|---|---|---|---|
| `blending` | `additive`, `punchthrough`, `default` | 4 / 226 | yes | How the texture blends. `additive`: add colour onto what is behind (glows, holograms, 172 textures). `punchthrough`: alpha-tested cut-outs, foliage, nets (56). `default`: normal alpha. One texture says `addititive` (a typo; treat as default). The exe knows only `additive` and `punchthrough`. |
| `decal` | `0`/`1` | 2 / 42 | yes | Drawn on top of the surface it lies flat against (door force fields, reticles, flares). |
| `mipmap` | `0`/`1` | 5,593 / 1,923 | yes | `0`: sample the top level only (GUI art, lightmaps, fonts). Default 1. |
| `filter` | `0`/`1` | 1 / 17 | yes | `0`: nearest-neighbour sampling (fonts, some GUI borders); `1` (default): linear. |
| `clamp` | `0`..`3` | 0 / 156 | yes | Clamp texture coordinates instead of wrapping: bit 0 = u, bit 1 = v (NWN). All uses are `3`, all on character head textures (`pfha01`, `pmhc02`, `p_carthh01`). |
| `downsamplemin`, `downsamplemax` | integer | 2 / 166, 5,590 / 588 | yes | Limits on how many levels the texture may be reduced by at lower texture quality; all values are `0` (never reduce). |
| `alphamean` | float | 0 / 1 | yes | One texture (`lda_gobo1`, `0.01`). NWN: how far to fade the alpha channel; exact use unknown. |
| `gamma` | float | 0 / 0 | yes | Not used by any texture. NWN: gamma correction. |
| `cube` | `1` | 0 / 63 | yes | The texture is a cube map (six faces; see the TPC rule above). |

### Environment and bump maps

| Keyword | Args | Resrefs | Exe | Meaning (best known) |
|---|---|---|---|---|
| `envmaptexture` | texture | 0 / 338 | yes | Environment map reflected on this surface. Resolves to a cube-map TPC for 320 textures (`CM_Baremetal` on 208 of them), to a plain 2D TPC for 15 (`gunmetal`, `fx_reflectmap`; how a 2D map is projected is for the rendering agent), and to nothing for 3. |
| `bumpyshinytexture` | texture | 3 / 107 | yes | Environment map for a bump-mapped shiny surface; always a cube-map TPC (`CM_SpecMap`, `CM_Dantne`), 4 missing. |
| `bumpmaptexture` | texture | 0 / 120 | yes | The bump map to use with this diffuse texture. The target's own TXI says `isbumpmap 1` (119; 1 missing): a DXT5/RGBA TPC (98), a grey TPC (4) or a TGA (17). |
| `isbumpmap` | `1` | 17 / 142 | yes | This texture is a bump map, not a colour texture. |
| `bumpmapscaling` | float | 17 / 133 | yes | Bump strength (`0.125` .. `5`). |
| `isdiffusebumpmap`, `isspecularbumpmap` | `0`/`1` | 0 / 35 each | yes | Seen together with `isbumpmap 1` on 35 wall, floor and rock bump maps (`leh_wall01b`, `lrk_flr02b`, `lka_mud02b`, `mgf_interiorb01`); meaning unknown. |
| `specularcolor` | 3 floats | 0 / 3 | yes | Specular colour for bump-mapped surfaces (`.5 .5 .5`). |
| `wateralpha` | float | 0 / 22 | yes | Opacity of water and puddle surfaces (`0.2` .. `1`). |
| `envmapalpha`, `isenvironmentmapped`, `bumpintensity`, `diffusebumpintensity`, `specularbumpintensity`, `useglobalalpha`, `temporary`, `maptexelstopixels`, `renderbmlmtype` | | 0 / 0 | yes | Read by the exe, used by no shipped texture. |

### Animation (flipbooks)

| Keyword | Args | Resrefs | Exe | Meaning (best known) |
|---|---|---|---|---|
| `proceduretype` | `cycle`, `arturo`, `water`, `ringtexdistort`, `random` | 18 / 54 | yes | `cycle`: a flipbook (below). The others are generated by the engine (next table). The exe also knows `wave`, `perlin` and `life`, unused. |
| `numx`, `numy` | integer | 16 / 41 | yes | Frames across and down. Values 1, 2, 4, 8 and 16 (`fx_tex_01` is 1 x 16). |
| `fps` | integer | 16 / 41 | yes | Frames per second (8 .. 32). |

A `cycle` texture shows `numx * numy` frames in turn, `fps` per second, looping. In a TPC the frames
are stored one after another, each with its own mip chain (see the TPC rule); in a TGA they are
cells of one image. The frame order within a TGA grid is for the rendering agent to confirm.

### Procedural textures

| Keyword | Args | Resrefs | Exe | Meaning (best known) |
|---|---|---|---|---|
| `defaultwidth`, `defaultheight` | integer | 2 / 12 | yes | Size of the generated image (32 x 32 mostly, one 16 x 16, four 32 x 14). |
| `channelscale`, `channeltranslate` | block of N numbers | 1 / 11, 1 / 12 | yes | Per-channel scale and offset of the generated values (N = 4: R, G, B, A). The exe also has `channelscale0`..`3` and `channeltranslate0`..`3`, unused. |
| `distort` | number | 0 / 13 | yes | Distortion mode or strength (`1`, `2`, `4`, `0.1`). |
| `distortionamplitude` | float | 0 / 13 | yes | Strength of the distortion. |
| `speed` | float | 0 / 13 | yes | Animation speed. |
| `arturowidth`, `arturoheight` | integer | 0 / 9 | yes | Grid size for the `arturo` generator. |
| `waterwidth`, `waterheight` | integer | 0 / 2 | yes | Grid size for the `water` generator. |
| `distortangle`, `anglecyclespeed`, `forcecyclespeed` | | 0 / 0 | yes | Unused. |

`arturo` and `water` textures (`lda_water00`, `lka_water01`, `lma_caus01`, `lka_plant01`) still have
pixel data; `distortiontex` (`ringtexdistort`) and `filmnoisetex` (`random`) have none and exist only
as a TXI. What the generators compute is not documented anywhere public; it is RE work.

### Fonts

18 font textures, all TPCs in `swpc_tex_gui.erf` with one mip level (`dialogfont10x10`,
`dialogfont16x16`, `fnt_galahad14`, `fnt_console`, ...).

| Keyword | Args | Exe | Meaning |
|---|---|---|---|
| `numchars` | integer | yes | Number of glyphs: 256 (13 fonts), 255 (4) or 127 (`fnt_console`). |
| `fontheight` | float | yes | Glyph cell height in units of 100 texels: `fontheight * 100` is exactly the cell height in pixels in all 18 fonts. |
| `baselineheight` | float | yes | Baseline position in the same units (`0.08` in a 10-pixel cell). Which edge it is measured from: for the rendering agent. |
| `texturewidth` | float | yes | Texture width / 100 (2.56 for 256 pixels) in all 18. |
| `spacingR` | float | yes | Extra space after each glyph (0 except `0.02` in one font). |
| `spacingB` | float | yes | Extra space between lines (always 0). |
| `upperleftcoords` | block: N lines `u v 0` | yes | Top-left corner of each glyph's cell, in texture coordinates 0..1. |
| `lowerrightcoords` | block: N lines `u v 0` | yes | Bottom-right corner. |
| `caretindent` | float | **no** | NWN keyword (12 fonts, `-0.01`); not read by KOTOR. |

Glyph *i* is the *i*-th line of each block, presumably for the character whose byte value is *i*;
the block count equals `numchars` in every font. The third number is always 0. Widths vary per
glyph (proportional fonts); heights are all `fontheight`, except 31 empty glyphs whose two corners
share one `v`. `u` runs left to right. **`v` counts from the first stored row of pixels**: the cell
of glyph *i* is pixel rows `v_lowerright * height` to `v_upperleft * height` of the image in file
order, and upper-left `v` is larger than lower-right `v` (4,444 glyphs; equal in the 31 empty ones). The first stored row is the bottom of the
glyph as displayed (cut out that way, the glyphs read upside down when rows print in file order),
so these are OpenGL-style coordinates for an image uploaded in file order.
`python kotor/tools/py/txi_probe.py --fonts` prints glyphs cut out this way.

### Keywords the engine does not read

| Keyword | Resrefs | Meaning |
|---|---|---|
| `islightmap` | 5,474 / 99 | Marks area lightmaps; a note for BioWare's texture tools. |
| `compresstexture` | 5,475 / 119 | Tool option (`0`: keep uncompressed). Misspelt `compresstexure` and `compress texture` once each. |
| `bumpmapscale` | 0 / 8 | Typo for `bumpmapscaling`; the game ignores it. |
| `caretindent` | 0 / 12 | NWN font keyword. |
| `type` | 0 / 1 | `Type 0` in one lightmap (`m50aa_01a_a000ap`). |

## Defaults

With no TXI, or for a keyword not given: blending default (alpha), not a decal, mipmaps on, linear
filtering, wrap in both directions, no downsampling limits, not a cube map, not animated, no
environment or bump map. (NWN documents the same defaults: mipmap 1, filter 1, clamp 0, gamma
1.0, downsamplemin 0, downsamplemax 15.)

## Quirks

- `grassinfo.txi` (`textures.bif`) is not texture info: one blank line, then
  `3 grass 5.0 1.5  0.5 0.6 0.3  0.5 0.6 0.3`. The exe never names it; ignore it.
- `lma_caus01`: channel block counts that disagree with the lines after them (Grammar, Blocks).
- Misspelt keywords and values, listed above. Treat them as unknown.
- `lbl_menudarr.txi` in the GUI pack says `mipmap 0` twice, with trailing spaces.
- Keyword case varies; texture-name case varies.

## Checked

`python kotor/tools/py/txi_probe.py` (a few seconds) reads every standalone TXI
(`kres.Game().every_entry('txi')`) and every TPC copy (`every_entry('tpc')`), finds the appended
text with the rule above, and parses everything with the grammar above:

- 11,536 TPCs: every one's trailing bytes are empty or ASCII text (0 failures); 189 cube maps, 121
  flipbooks (all 121 match the frames-with-mip-chains layout), 6,207 with TXI.
- 5,616 standalone and 6,207 appended texts parsed, 0 failures; counts, values, case and layout
  as above.
- No resref has both a standalone and an appended TXI; the three quality packs agree for every
  resref.

`--dump kotor/extract/text/txi` writes each distinct text (24 standalone, 253 appended) there for
reading. `--fonts` (needs the texture agent's `tpcprobe.py`) prints glyph cells as text.
